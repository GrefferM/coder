# plain/ — звичайний HTML двох полотен

Ті самі документи, тільки без gzip: сторінка лежить у файлі текстом.
Працює пошук, працює `git diff`, кадр можна прочитати очима.

- `coder-design-plain.html` — перше полотно, 125 кадрів (~1,62 млн символів, ~14,1 тис. рядків)
- `coder-design-plain-2.html` — друге полотно, кадри 23f–23n, 23r, 23t–23x, 24g–24i і 24k
- `support.js`, `fonts/` — те, що вони підвантажують із тієї ж папки
- React — зовнішня залежність (React 18.3.1, UMD з unpkg), тому цим сторінкам
  потрібен інтернет; офлайн тримають бандли `Полотно пайплайну - офлайн.html` і
  `Полотно пайплайну 2 - офлайн.html` — інших бандлів у постачанні немає, щоб не було
  двох файлів одного полотна різного віку

## Подвійний клік

Браузер блокує `fetch` до сусіднього файлу з `file://`, тому подвійним кліком
сторінка малює кадри, але не сфери. Дивитись її треба з-під сервера — або взяти
бандл `Полотно пайплайну - офлайн.html`, де компоненти й React лежать усередині.

`Sphere.dc.html`, `Rail`, `Toolbar`, `ProjectChip` лежать поряд як
джерело правди: сторінка читає саме їх, і бандл збирається з них же.

## Як шукати кадр

Кожен кадр починається рядком `<div id="17a" ...`. Пошук по `id="17a"` веде рівно туди.
У двох кадрів номер без літери — `id="11"` і `id="43"`; це звичайні кадри, і в лічбу вони входять.
`id` і підпис кадру завжди однакові, штрихів у номерах немає: кадри другого полотна — 23f–23n, 23r, 23t–23x, 24g–24i і 24k.
Карта всіх 144 кадрів — у `../Карта кадрів.md`, на рівень вище.

## Як цей файл з'являється

`coder-design-plain.html` — це копія `Полотно пайплайну.dc.html` без жодної правки,
`coder-design-plain-2.html` — така сама копія `Полотно пайплайну 2.dc.html`,
разом із тими самими `support.js`, чотирма компонентами й `fonts/`. Перезбирати їх
треба щоразу, коли міняється відповідне полотно — інакше експорт приїжджає старіший за кадри.
Друге полотно малює деталі панелі й компонентів не читає, тому подвійний клік по ньому дає повну картинку.
